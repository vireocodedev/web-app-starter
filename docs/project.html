Adaptive client discovery

Rounds and decisions

Model the interview as a decision tree with stable question IDs and explicit prerequisites. The frontier contains all unresolved questions whose prerequisites are settled. Ask that whole frontier in one round; a question dependent on another question in the same round belongs to a later round. Save partial replies and recompute the frontier. The tree can grow when answers reveal new branches.

Use this format and number continuously across the conversation:

❓ Q1 — Problem: Which recurring problem should this app solve, for whom,
and what happens today? Is this proposed description accurate: ...?
➡️ Recommended: ... because ...

❓ Q2 — Decision owners: Are you the person who can approve product scope,
and who will accept the completed app?
➡️ Recommended: record named responsibilities before accepting requirements.

Word a question so “yes” accepts the recommendation when a defensible recommendation exists. For unknown client facts, ask the open question, explain why it matters and say there is not enough evidence for a recommendation. Avoid invented client facts, forced defaults, fixed questionnaire length and repeat questions answered by sources. Ask applicable branches together without inventing answers to unblock others.
