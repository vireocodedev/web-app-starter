# Rehearsal lessons

These are generic prevention rules from an earlier consumer rehearsal, not
acceptance evidence for this template or another consumer. A clean
fresh-consumer run is still required to prove the complete no-follow-up
initialization experience.

| Observed bottleneck                                                | Required prevention                                                                                              |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| CLI identity differed from the repository owner                    | Select the protected account/profile before invocation; verify access and prefer scoped authentication.          |
| Existing application/database identity was ambiguous               | Record fresh versus same-identity resume and preserve existing resources.                                        |
| Identity, artwork, accounts and backup risk needed human decisions | Collect explicit intake answers before bulk changes.                                                             |
| Operator/profile discovery happened late                           | Arrange the existing operator reference and verify current source, trust, receipt and capacity upfront.          |
| Selected-repository App access needed owner browser consent        | Complete the existing App's saved repository selection beforehand; repository administration alone is not proof. |
| Old image namespaces belonged to different repositories            | Inspect package ownership, preserve by default and stop for separately authorized replacement.                   |
| Port defaults collided with another application                    | Verify ownership and allocate only approved unused ports; update all dependent surfaces.                         |
| IDE import name differed from Gradle identity                      | Omit the optional single-backend `projectName`; verify the actual saved launch after personalization.            |
| Generic Java launch did not prove saved IDE launches               | Verify an unattended tool path for both configurations during readiness, then test real launches.                |
| Empty reviewer settings invoked unavailable private-plan features  | Omit unused protection fields and verify actual readback; do not upgrade plans implicitly.                       |
| A Python isolation flag hid an installed CLI's sibling modules     | Use the operator-documented interpreter/entrypoint; verify `--help` and real backup behavior.                    |
| A transient container startup failed CI                            | Keep the failing required check; diagnose/retry within scope without weakening isolation.                        |

Human login/2FA, App consent, credential entry, identity/risk choices and execution
consent remain human tasks. The agent records those answers during intake; only live
verification can establish runtime, CI, deployment and initialized recovery
acceptance. Unexpected post-intake assistance is a preparation defect to record,
not a reason to claim a no-follow-up success.
